# Retro — Epic 1 (Authentication & Access Control)

## Project
Meridian Corp LMS — Epic 1 (TASK-010…016 + logout). Solo dev, AI-assisted (OpenCode). 2026-08-07.

## What Worked
- **EVAP's EVALUATE gate caught real bugs before any code was written**: unquoted CHECK literals (TASK-008), profiles-policy infinite recursion (TASK-011), the service_role BYPASSRLS misconception, the note-only-UPDATE NULL-action crash (TASK-013).
- **Throwaway postgres:16 container** verified migrations/constraints/idempotency without a CLI in-session.
- **Per-role anon-client RLS integration tests** enforce policies for real (not false-green) — reused seed UUIDs via the trigger's ON CONFLICT to mint auth users.
- **Local Supabase emulator + Mailpit** made magic-link auth testable end-to-end with no email rate limits.

## What Didn't Work
- **Spec-vs-reality drift everywhere** cost repeated correction time: route naming (/admin vs /hradmin, /login vs /auth/login), `middleware.ts` vs Next 16 `proxy.ts`, Jest vs Vitest, Inbucket vs Mailpit, SECURITY DEFINER omitted from task specs, and no logout task at all.
- **TASK-005 CI was under-verified** — three separate regressions surfaced later: Node 20 vs 22 (supabase-js WebSocket), an unguarded Vercel step, and `supabase db push --project-ref` (invalid flag).
- **`server.ts`'s empty `setAll`** was a cookie/redirect-loop trap for both login callback and logout.

## What We'd Do Differently
- Run a **spec-vs-codebase audit at the start of each epic** (routes, tool names, versions) — Owner: Dev → flag to Tech Lead/SA.
- **Verify infra/CI tasks against their acceptance criteria** before marking done — Owner: Dev.
- **Stand up the local emulator (Docker) on day 1**, not mid-epic — Owner: Dev.

## Top 3 Reusable Assets
1. `knowledge/patterns/verify-migration-in-container.md` — container-based migration/seed verification.
2. Per-role anon-client RLS integration-test approach (`tests/integration/helpers.ts`).
3. The `migration-task` and `dev-task-generation` EVAP prompt sets (`knowledge/prompts/`).

## Top 3 Pitfalls
1. `service_role` bypasses RLS — never assert RLS behavior through it.
2. Any function writing to an RLS/grant-restricted table must be SECURITY DEFINER, or every write fails.
3. Don't trust task-spec wording — verify routes, tool names, and versions against the actual codebase.
